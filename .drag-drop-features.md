# Drag & Drop primitives — comprehensive feature survey

Research-backed master list of every capability the popular drag-and-drop /
sortable / reorderable libraries collectively support, to scope a headless
Angular DnD primitive for ng-primitives.

**Confidence key.** ✅ = confirmed by adversarial verification against primary
vendor docs (dnd-kit, Angular CDK, React Aria, Atlassian Pragmatic DnD). ◒ =
extracted from a primary source file (library source / official docs) in a
second research pass whose adversarial-verify step was cut off by a session
limit — sourced, but not cross-checked; exact numbers carry a "confirm before
copying" caveat. ◓ = well-established behaviour of a library the verified corpus
under-sampled (GridStack, Muuri, interact.js, Vue Draggable); treat as design
input, not a citation.

Reference libraries by role:

- **dnd-kit** — layered framework-agnostic core + DOM + thin adapters; sensors,
  swappable collision, accessibility out of the box. The API-design reference.
- **Angular CDK Drag & Drop** — connected lists, transfer/copy, preview &
  placeholder directives, axis/boundary/handle constraints, enter/sort
  predicates. The declarative-Angular reference.
- **React Aria + Atlassian Pragmatic DnD** — the accessibility and
  drop-indicator gold standard (keyboard model, live-region announcements,
  hiding non-targets from AT, pixel-precise tree drop indicators).
- **SortableJS / react-beautiful-dnd** — the "batteries-included sortable"
  reference (animation, groups, ghost/chosen classes).

---

## 1. Core drag mechanics

- ✅ **Pointer-based drag engine** (transform-follows-cursor) vs ✅ **native
  HTML5 DnD** engine — two fundamentally different foundations. Pointer engines
  (dnd-kit, CDK, SortableJS) give full control, mobile + keyboard parity, and
  custom previews, but **cannot** do OS/file/cross-window/cross-iframe drag.
  Native HTML5 DnD (react-dnd HTML5 backend, React Aria) is the _only_ path to
  OS integration but is notoriously quirky — React Aria normalizes ~13 browser
  bugs on top of it.
- ✅ **Activation constraints** before a drag begins: distance threshold
  (px moved), delay/hold (ms), and tolerance (px of jitter allowed during a
  delay). Distinguishes a click from a drag.
- ◓ **Grab/anchor offset** — preserve the pointer's position within the item so
  the ghost doesn't jump to a corner on grab.
- ✅ **Drag lifecycle**: activate → start → move/over → drop/end → cancel.
- ◓ **Programmatic drag start / cancel** (start a drag from code, abort in
  flight).
- ◓ **Drag threshold direction bias** (only start once movement is primarily
  along the sortable axis) — SortableJS `direction`.

## 2. Sortable / reorderable lists ✅

- ✅ **Single-list reorder** with live shifting of siblings as you drag.
- ✅ **Orientation**: vertical, horizontal, and **mixed / wrapping** (grid-like
  flow) — CDK `cdkDropListOrientation`, dnd-kit sorting strategies.
- ✅ **Sorting strategies** (dnd-kit): `rectSortingStrategy` (default),
  `verticalListSortingStrategy`, `horizontalListSortingStrategy`,
  `rectSwappingStrategy` (swap instead of shift). Note: only the vertical/
  horizontal strategies support virtualized lists; the default rect strategy
  does not.
- ✅ **Swap vs insert/shift** semantics as a choice.
- ◓ **Sort during drag toggle** (SortableJS `sort:false` = drop target only, no
  internal reordering).
- ✅ **Sort predicate** — gate whether an item may land at a given index
  (CDK `cdkDropListSortPredicate`).
- ◓ **Fixed / non-sortable items** pinned in place while others move around
  them (`filter`, `draggable` selectors).

## 3. Multi-list / cross-container drag ✅

- ✅ **Connect lists** explicitly by reference or by id
  (CDK `cdkDropListConnectedTo`), or **auto-connect** siblings via a group
  wrapper (`cdkDropListGroup`, SortableJS `group`).
- ✅ **Transfer** (move item between lists) and ✅ **copy/clone** (duplicate,
  keep original) — CDK `transferArrayItem` / `copyArrayItem`; SortableJS
  `group: { pull: 'clone' }`.
- ◓ **Directional group rules**: `pull` / `put` (what a list emits vs accepts),
  named groups, `put` allow-lists.
- ✅ **Enter predicate** — which items a container will accept
  (CDK `cdkDropListEnterPredicate`); the validation hook that lets the library
  stay data-agnostic.
- ⚠️ **Known limitation**: CDK group auto-connect works for _sibling_ lists, not
  lists structurally nested inside each other → relevant to trees (§10).

## 4. Grids & 2D layouts

- ✅ **Item model as data** — react-grid-layout represents the grid as an array
  of item descriptors: `{ i, x, y, w, h, minW, maxW, minH, maxH, static,
isDraggable, isResizable }` (`i` = key, `x/y` = grid cell, `w/h` = span in
  cells; `minW/minH` default 0, `maxW/maxH` default Infinity). GridStack uses
  the same short `w/h/minW/maxW/minH/maxH` keys (renamed from legacy
  `width/height/minWidth`). The layout array is the serialization format — a
  headless grid primitive should adopt this "layout is a signal of item rects"
  shape.
- ✅ **Multi-cell spans** — `w`×`h` in grid units with per-item min/max clamps
  (react-grid-layout, GridStack both confirmed).
- ✅ **Static / locked items** — `static: true` pins an item (not draggable or
  resizable, others flow around it); per-item `isDraggable`/`isResizable`
  override it (react-grid-layout).
- ✅ **Resize handles (1D & 2D)** — react-grid-layout `resizeHandles:
Array<'s'|'w'|'e'|'n'|'sw'|'nw'|'se'|'ne'>`, default `['se']` (south-east
  corner). interact.js `resizable` + `snapEdges()`/`snapSize()` modifiers;
  GridStack resize built in. React Aria lists "resizing an object in one
  dimension" as one of the four canonical accessible DnD patterns — resize
  deserves the same keyboard/ARIA treatment as drag.
- ✅ **Responsive per-breakpoint layouts** — react-grid-layout
  `ResponsiveGridLayout`: `breakpoints` (default `{lg:1200, md:996, sm:768,
xs:480, xxs:0}`), `cols` per breakpoint (default `{lg:12, md:10, sm:6, xs:4,
xxs:2}`), and a `layouts` map storing a separate layout per breakpoint.
- ✅ **Serialization** — GridStack ships `grid.save()` → serializable widget
  list (optionally grid options + HTML) and `grid.load(saved)` to restore, with
  add/remove callbacks. react-grid-layout serializes via its layout array.
- ✅ **Snapping (free 2D)** — interact.js `interact.modifiers`: `snap()` (snap
  pointer coords to targets during drag), `snapSize()` (snap dimensions on
  resize), `snapEdges()` (snap edges on resize). Grid snap via
  `interact.snappers.grid({ x, y, range?, offset?, limits? })` (`x/y` = grid
  line spacing).
- ✅ **Pluggable layout function** — Muuri takes a `layout` function called with
  container width/height + active items, returning positions
  `[aLeft,aTop,bLeft,bTop,…]`; default is bin-packing. This is the "free 2D /
  arbitrary placement" escape hatch vs a fixed grid.
- ✅ **Cross-grid drag + repack** — Muuri `dragSort` (sorting), `dragSort
Predicate.migrateAction: 'move' | 'swap'` (between separate grids),
  `dragAxis`, `dragAutoScroll`. GridStack/Muuri repack on drop; Muuri animates
  the repack.
- ◒ **Compaction / collision-free repacking** — react-grid-layout `compactType:
'vertical' | 'horizontal' | null` (legacy `verticalCompact`, default true)
  reflows tiles to fill gaps after a move. The hard core of grid DnD: every move
  can cascade-move other items.
- ◓ **Free 2D positioning** on a canvas (dnd-kit translate, Framer Motion
  `drag`) — move an object to any x/y, not snapped.
- ◓ **Bounded dragging** — constrain within container bounds (react-grid-layout
  `isBounded`; dnd-kit `restrictToParentElement` modifier).
- ◓ **Drag-in from outside** — drop an external element to create a tile
  (react-grid-layout `droppingItem` + `onDrop`; GridStack `acceptWidgets`).

> Grids/2D remain an **advanced tier** for the primitive, but the API surface is
> now well-mapped: react-grid-layout's item-model + compaction is the reference,
> GridStack adds save/load, interact.js/Muuri cover free-placement snapping.

## 5. Drop zones & drop targets ✅

- ✅ **Droppable regions** independent of sortable lists (a zone that accepts a
  drop without reordering).
- ✅ **Accept/reject by data type** — targets that only accept matching payloads
  (React Aria types; react-dnd `accept`).
- ✅ **`isOver` / active-target state** for styling the hovered target.
- ◓ **Nested droppables** with hit priority (innermost wins) — react-dnd,
  Pragmatic DnD.
- ◓ **Whole-container "combine/drop-on" operation** (drop _onto_ an item, not
  between) — see tree reparenting (§10), react-beautiful-dnd `combine`.

## 6. Drag previews / ghosts / clones ✅

- ✅ **Custom preview** separate from the source element — CDK `*cdkDragPreview`
  (default is a clone), SortableJS drag/ghost classes.
- ✅ **Preview render container**: `global` (body/overlay), `parent`, or a custom
  element — CDK `cdkDragPreviewContainer` — to escape `overflow:hidden` /
  stacking-context clipping.
- ✅ **Match size** of the original (`matchSize`).
- ◓ **Preview offset / cursor anchor** and **preview transform** (rotate/scale,
  react-beautiful-dnd lift animation).
- ◓ **Ghost/chosen/drag CSS class hooks** on the origin during drag (SortableJS
  `ghostClass`, `chosenClass`, `dragClass`).
- ✅ **Native drag image** control when on the HTML5 backend
  (`setDragImage`, React Aria custom preview).
- ◓ **Multi-item stacked preview** (a "badge" showing N items) — React Aria /
  Pragmatic multi-drag.

## 7. Drop placeholders & indicators ✅

- ✅ **Placeholder** (gap showing where the item will land) as a **separate**
  concern from the preview — CDK `*cdkDragPlaceholder`.
- ✅ **Insertion-line indicator** (between-items line) with a precise spec —
  Atlassian: 2px line in `color.border.selected`, centred in the gap, 8px
  terminal bleeding 4px outward, **hidden when no valid relative placement
  exists**.
- ✅ **Semantic drop labels** for SR: "Insert between item A and item B"
  (React Aria).
- ◓ **Drop-on highlight** (outline the target item for a combine/reparent).

## 8. Collision / hit-detection strategies ✅

- ✅ **Swappable strategy, not hardcoded** — expose collision detection as a
  pluggable function. dnd-kit ships `pointerIntersection` (pointer inside rect),
  `shapeIntersection` (greatest overlap area), `closestCenter`,
  `closestCorners`, `pointerDistance`, `directionBiased`, `rectIntersection`.
- ⚠️ **Do not over-prescribe per-layout guidance** — the specific claim
  "closestCenter for grids / closestCorners for lists" was **refuted**. Offer
  the strategies; let the consumer pick.
- ◓ **Custom collision composition** (chain/fallback strategies) — dnd-kit
  allows composing detectors.

## 9. Auto-scroll

- ✅ **dnd-kit AutoScroller `Options`** (`useAutoScroller.ts`): `acceleration`
  (base speed multiplier; default **25** in the newer plugin), `threshold:
{ x, y }` (activation zone as a **fraction** of container size, default
  `{ x: 0.2, y: 0.2 }`; set an axis to `0` to disable it), `interval` (default
  **5** ms), `enabled`, `order` (`TraversalOrder`, default `TreeOrder`),
  `activator` (`AutoScrollActivator.Pointer` default, or `DraggableRect`),
  `canScroll` predicate, and `layoutShiftCompensation`. Direction + speed come
  from `getScrollDirectionAndSpeed(container, containerRect, rect, acceleration,
threshold)`, gated on `speed.x > 0 || speed.y > 0`.
- ⚠️ **Version-pin the defaults** — dnd-kit v6 (the still-dominant stable line)
  used an `autoScroll` prop on `DndContext`; the newer v2 plugin uses the
  `acceleration: 25` / `threshold: 0.2` numbers above. Some docs cite `15` /
  `0.3`. Confirm the target version before copying constants.
- ✅ **Per-axis + oversized-item guard** — auto-scroll runs per axis
  independently; hello-pangea/rbd **declines to scroll an axis** when the
  draggable is larger than the container on that axis, keeping the other axis
  live.
- ✅ **Nested scroll containers** — dnd-kit traverses scrollable ancestors in
  `TraversalOrder` and scrolls the first matching `canScroll`. "Which ancestor
  scrolls" = walk up, pick the innermost eligible scroller.
- ✅ **rbd / hello-pangea trigger + curve** — auto-scroll fires when the
  **center of the draggable** comes within a **percentage** of the container
  edge (not fixed px, so it's container-size-responsive), and speed ramps via an
  easing function that **exponentially** increases toward the edge, hitting max
  a small distance before the true edge (forgiving of imprecision). Tunable via
  `autoScrollerOptions`: `startFromPercentage`, `maxScrollAtPercentage`,
  `maxPixelScroll`, `ease`, `durationDampening.{startDampeningAt, accelerateAt}`,
  `disabled`.
- ✅ **Scroll while keyboard-dragging is solved** (rbd/hello-pangea) — it
  updates scroll position during keyboard drags by combining droppable scroll +
  window scroll + manual movement, explicitly as an a11y benefit for moving
  items through long lists without a mouse. (Revises my earlier "genuine gap"
  note — it's doable; rbd is the reference.)
- ✅ **Muuri `dragAutoScroll`** — `targets` array (elements / scroll-target
  objects / function, per-axis via `AXIS_X`/`AXIS_Y`, so **multi-container**,
  not window-only), `threshold` (default **50** px), `safeZone` (0.2), `speed`
  (`smoothSpeed(maxSpeed, acceleration, deceleration)` = `smoothSpeed(1000,
2000, 2500)`), `sortDuringScroll` (true), `smoothStop` (false).
- ✅ **Angular CDK** — `cdkDropListAutoScrollStep` (`autoScrollStep` input),
  px/frame, default **2** (since v11.1.0; runs via `requestAnimationFrame`).
  `cdkDropListAutoScrollDisabled` turns it off.
- ◓ **SortableJS** — `scroll` (element or bool), `scrollSensitivity` (px from
  edge to start), `scrollSpeed` (px/frame), `bubbleScroll` (walk up parent
  scrollers).

> **Design steer for the primitive:** copy dnd-kit's `Options` shape —
> `threshold` as a 0-1 fraction per axis (0 disables), an `acceleration` speed
> multiplier, a `canScroll` predicate, innermost-eligible-ancestor selection.
> Trigger on the **draggable center** (rbd) not just the pointer so keyboard
> drags work, use an eased (not linear) speed curve, and support a `targets`
> array for multi-container. Drive it off a signal of the active rect vs cached
> scroll-container rects, stepped on `requestAnimationFrame`.

## 10. Nested / tree drag-drop ✅ (hard)

- ✅ **Flatten-the-tree approach** — represent the tree as a single flat sortable
  list (with depth metadata) rather than nesting sortable contexts, which
  block cross-level dragging. (Matches ng-primitives' existing flat
  `visibleNodes()` tree design.)
- ✅ **Reparent / "combine" operation** — drop _onto_ a node to make it a child.
- ✅ **Hover auto-expand** — collapsed node expands after **500ms** of combine-
  hover; expansion persists after drop (Atlassian).
- ✅ **Keep dragged item visible after drop**, expanding ancestors as needed.
- ◓ **Depth/indent drop indicator** — horizontal position of the line encodes
  target depth (Atlassian tree, dnd-kit tree example).
- ◓ **Valid-parent constraints** (prevent dropping a node into its own
  descendant).

## 11. Constraints ✅

- ✅ **Axis lock** — x / y only (CDK `cdkDragLockAxis`, dnd-kit
  `restrictToVerticalAxis`).
- ✅ **Boundary containment** — constrain within an element/selector
  (CDK `cdkDragBoundary`, dnd-kit `restrictToParentElement` /
  `restrictToWindowEdges`).
- ✅ **Drag handles** — only a sub-element initiates drag (CDK `cdkDragHandle`,
  SortableJS `handle`); multiple handles.
- ✅ **Start delay / hold-to-drag** (CDK `cdkDragStartDelay`; touch long-press).
- ✅ **Disabled items / disabled list** (CDK `cdkDragDisabled`,
  `cdkDropListDisabled`).
- ◓ **Snap-to-grid / step** modifiers, **min/max position clamps**.
- ◓ **Modifier pipeline** (dnd-kit `modifiers`) — composable transforms on the
  live drag position; the general form the above are special cases of.

## 12. Sensors & input ✅

- ✅ **Pluggable sensors**: Pointer, Mouse, Touch, Keyboard (dnd-kit); Pointer +
  Keyboard on by default.
- ✅ **Pointer Events as the unifying primitive** (one code path for mouse/touch/
  pen) with activation constraints per sensor.
- ✅ **Keyboard sensor** (see §13).
- ◓ **`touch-action` / passive-listener** handling to prevent scroll-vs-drag
  conflict on mobile.
- ◓ **Custom sensors** (e.g. gamepad, long-press variant) via the sensor
  contract.

## 13. Accessibility ✅ (strongest-evidenced area — baseline, not an add-on)

- ✅ **Keyboard-operable drag** — two reconcilable models; pick one primary and
  make keys configurable:
  - dnd-kit / CDK-proposal model: **Space/Enter** pick up, **arrows** move,
    **Escape** cancel, Space/Enter drop.
  - React Aria collection model: **Enter** start, **Tab** only between accepting
    targets, **arrows** choose position, **Enter** drop, **Escape** cancel.
- ✅ **Live-region announcements** via an off-screen ARIA live region: start (+
  instructions), over, drop success, cancel. Prefer **position-based** ("2 of
  5") over index-based phrasing. Customizable message set.
- ✅ **Default ARIA on draggables** — `role=button`,
  `aria-roledescription=draggable`, `aria-describedby`, `tabindex=0` (all
  overridable) — dnd-kit applies these automatically.
- ✅ **Hide non-target elements from AT during a drag** so SR users tab/swipe
  only through valid targets (React Aria) — makes large collections tractable.
- ✅ **Localized announcements** (React Aria: 30+ languages, device-adapted).
- ✅ **Alternative: action-menu pattern** ("Move to…" menu) — Atlassian user
  testing found menus _outperform_ directional keyboard drag on
  discoverability, reliability, and cost. Worth offering as a first-class
  a11y affordance alongside keyboard drag.
- ✅ **Focus management** — return focus sensibly after drop/cancel; native
  focusable controls per item (Dragon Drop pattern).

## 14. Animations & transitions

- ◒ **FLIP technique** (First, Last, Invert, Play — Paul Lewis) is how every
  library animates reorder cheaply: measure each item's rect **before** the DOM
  reorder (First) and **after** (Last); apply an inverse `transform` so it still
  _looks_ like it's at the old spot (Invert); then enable a transition and
  remove the transform so it animates to the new spot (Play). It's performant
  because it only animates compositor-friendly `transform`/`opacity`, never
  layout-triggering properties.
- ◒ **dnd-kit** — `useSortable` `transition` defaults to `{ duration: 200,
easing: 'ease' }`, animates the `transform` property only, and
  `transition: null` disables it. Sibling-shift-during-drag is gated by the
  `animateLayoutChanges` / `defaultAnimateLayoutChanges` hook (control when a
  layout change animates vs snaps).
- ◒ **SortableJS** — `animation` = duration in ms (default **150**; `0`
  disables), `easing` accepts any CSS timing function / cubic-bezier (default
  `null`).
- ◒ **Framer Motion `Reorder`** — `Reorder.Group` takes `values` + `axis`
  (default `'y'`) + `onReorder`; each `Reorder.Item` has a `value` identity
  prop. Layout (FLIP) animation is **automatic** on add/remove/reorder; identity
  tracked by `value`. Uses springs by default (vs the CSS tweens above).
- ◓ **Drop-settle animation** — item eases from the drag position into its
  final slot on release (rbd's drop animation, dnd-kit drop animation config).
- **Identity is load-bearing** — FLIP needs stable per-item keys/ids to match
  First↔Last rects; the same ids power SR announcements (§13) and virtualization
  (§15). One identity model, three consumers.
- **`prefers-reduced-motion`** — collapse durations to 0 / skip the Play step
  when set. None of the sources spell this out; make it a first-class default in
  the primitive (ng-primitives already respects reduced-motion elsewhere).
- ⚠️ **Spring vs tween** — Motion uses springs (velocity-aware, interruptible);
  SortableJS/dnd-kit/CDK use CSS tweens (duration + easing). Tweens are simpler
  and headless-friendly; expose duration+easing, leave springs to the consumer.

## 15. Virtualization compatibility

- ◒ **Why the default strategy breaks** (dnd-kit discussion #411): the default
  `rectSortingStrategy` needs **every** item mounted to measure its rect, which
  a windowed list by definition doesn't do — so it can't support
  virtualization. `verticalListSortingStrategy` / `horizontalListSortingStrategy`
  **do**, because they compute shifted positions arithmetically from a single
  item size + index rather than from all measured rects. Takeaway: a
  virtualization-capable sort strategy must be **index/size arithmetic**, not
  all-rects-measured.
- ◓ **Measured-rect caching + re-measure on scroll** — the windowing lib
  (react-window / TanStack Virtual / CDK `*cdkVirtualFor`) owns which items are
  mounted; the DnD layer must read item geometry from the virtualizer's index→
  offset map and re-derive on scroll, not cache stale rects.
- ◓ **Dragging past the viewport edge** — the dragged item can scroll out of
  the rendered window; needs auto-scroll (§9) to advance the virtualizer and a
  drag overlay that survives the source item being unmounted (dnd-kit
  `DragOverlay` renders the preview outside the list so recycling the source row
  doesn't kill the drag).
- ⚠️ **This is the hardest interop** — virtualization (unmount offscreen) fights
  DnD (needs geometry of items you can't see) fights FLIP (needs First/Last
  rects of items that may not both be mounted). Aligns with the ng-primitives
  tree design already being **flat `visibleNodes()` + single `@for`** — that
  flat, index-addressable model is exactly what a `*cdkVirtualFor` swap needs.

> **Design steer:** make the sort strategy pluggable (§2) and ship an
> arithmetic vertical/horizontal strategy as the virtualization-capable one;
> render the drag preview in an overlay decoupled from the list so item
> recycling can't interrupt a drag.

## 16. File / OS drag-drop ◓ (native-backend only)

- ✅ **Requires native HTML5 DnD** — file-from-OS, drag-into-app, cross-window/
  iframe/app all need the native backend and its bug-normalization burden
  (React Aria).
- ◓ **File drop zones** (`dataTransfer.files`), directory drop, external text/
  URL drop, drag-_out_ to OS.

## 17. Multi-item / selection drag ◓ / ✅(partial)

- ✅ **Multi-item drag** — select N items and drag them together
  (React Aria, Pragmatic DnD, SortableJS MultiDrag plugin).
- ◓ **Selection integration** (drag preserves/uses an existing selection
  model), **stacked count preview**, per-item vs group drop.

## 18. Controlled vs uncontrolled & data model ✅(pattern)/◓

- ◓ **Library stays data-agnostic** — it reports intent (from/to index,
  container, item id) and the consumer mutates the array. CDK's
  `transferArrayItem`/`copyArrayItem` are helpers, not owned state. This is the
  ng-primitives `controlledState` fit.
- ◓ **Controlled** (consumer owns order) vs **uncontrolled** (internal order
  with change output).
- ◓ **Item identity** by key/id for stable animation and SR announcements.

## 19. Events / lifecycle hooks ✅

- ✅ Start, move, enter/over (per container), exit, drop (with from/to
  index+container), end, cancel.
- ◓ **Predicate hooks** (enter, sort — §3/§2) as validation, distinct from
  notification events.
- ◓ **Both imperative callbacks and observables/outputs** (Angular idiom).

## 20. Performance techniques ◓

- ◓ **Transform-based movement** (translate, no layout thrash), **rAF-batched**
  pointer handling.
- ◓ **Measure-once rect caching** per drag; recompute on scroll/resize only.
- ◓ **Avoid re-render storms** — dnd-kit's abstract core keeps drag math out of
  the framework's change detection (zoneless-friendly for Angular).
- ◓ **Passive event listeners** where possible; `will-change`/compositor hints.

## 21. Architecture & headless tradeoffs ✅

- ✅ **Layered, framework-agnostic core** (dnd-kit: `@dnd-kit/abstract` core +
  `@dnd-kit/dom` + thin adapters) is the proven shape — keep drag logic in a
  framework-neutral state layer, Angular directives as a thin binding shell.
  Fits ng-primitives' `createPrimitive` / `-state.ts` pattern exactly.
- ✅ **Headless = behaviour + ARIA + data hooks, zero visual opinion**; consumer
  owns all styling (ghost, placeholder, indicator are slots).
- ⚠️ **Version drift caution**: dnd-kit's newer `@dnd-kit/dom` generation
  (`pointerIntersection`/`shapeIntersection`, layered pkgs) differs from the
  still-dominant stable `@dnd-kit/core` (React-only, `pointerWithin`/
  `rectIntersection`). Confirm which generation before copying API names.

## Prioritization for a headless Angular primitive

**Tier 1 — non-negotiable baseline.** Core pointer drag engine + activation
constraints (§1); single-list sortable with orientation + sort strategies (§2);
multi-list connect / transfer / copy / enter+sort predicates (§3); accessibility
as a baseline — keyboard model, live-region announcements, default ARIA, focus
management, action-menu alternative (§13); data-agnostic controlled/uncontrolled
model + lifecycle events (§18/§19); layered framework-neutral state architecture
(§21).

**Tier 2 — core-plus.** Custom preview + placeholder + insertion-line indicator
with render-container control (§6/§7); swappable collision detection (§8);
constraints — axis/boundary/handle/delay/disabled + modifier pipeline (§11);
sensor abstraction incl. touch/long-press (§12); auto-scroll (§9); FLIP reorder

- reduced-motion (§14); drop zones with type accept/reject (§5).

**Tier 3 — advanced differentiators.** Nested/tree drag with reparent + hover
auto-expand + depth indicator (§10, aligns with existing tree primitive);
virtualization compatibility (§15); grids / 2D / resize / packing (§4);
multi-item selection drag (§17); OS/file drag via an optional native backend
(§1/§16).

## Open questions before building (from the research)

1. **Default engine**: pointer-based (control, mobile + keyboard parity, no OS
   drag) vs native HTML5 (OS/file drag, ~13 browser bugs) vs hybrid per use
